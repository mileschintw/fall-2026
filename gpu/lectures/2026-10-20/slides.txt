SIMD versus SIMT 
SIMT = Single Instruction Multiple   Threads   (NVIDIA term) 
Both models run one instruction over many ALU lanes at once. 
They differ in   what the programmer writes   and   what the hardware automatically 
CPU SIMD 
the   vector   is the unit of programming: 
one thread issues instructions on wide registers, 
programmer (or compiler) explicitly manage width, masking, and data layout. 
NVIDIA’s SIMT 
the   scalar thread   is the unit of programming: 
programmer declares independence of   cuda   kernel threads, 
the hardware groups 32 threads into a   warp   that runs on SIMD lanes. The 
hardware implicitly handles masking, divergence, per - lane addressing, and 
latency hiding at run time.

Warps as Scheduling Units 
•   Each Block is executed as   32 - thread Warps 
–   Once a block is assigned to an SM, it is divided into 32 - thread warps. 
–   An implementation decision, not part of the CUDA programming model 
–   Warps are scheduling units in SM 
–   Blocks are partitioned into warps based on 
consecutive increasing thread indices 
–   For 1D grid 
–   warp0 =   threadIdx   0   –   31 
–   warp1 =   threadIdx   32   –   63 
–   For 2D/3D grid 
–   dims projected row - major order 
–   Threads in a warp execute in SIMD “lanes” 
–   Partial warps padded with inactive threads 
–   Future GPUs may have different number of threads 
in each warp

Example: Warp/Thread Scheduling (Cont.) 
–   SM implements   zero - overhead warp scheduling 
–   Warps whose next instruction have operands ready for consumption 
are eligible for execution 
–   Eligible Warps are selected for execution based on a prioritized 
scheduling policy 
–   All threads in a warp execute the same instruction when selected 
–   SIMT model (allows writing scalar kernel code which uses SIMD HW) 
–   Warp - level primitives 
–   collection of API functions which provide efficient data exchange and 
synchronization across threads in a warp 
–   Warp Vote / Match / Reduce / Shuffle / _ _sync 
–   Treat warps as an extra level in software hierarchy (between blocks 
and threads)

__global__ void   MatrixMulKernel (float* M, float* N, float* P, Int Width) 
{ 
__shared__   float   ds_M [TILE_WIDTH][TILE_WIDTH]; 
__shared__   float   ds_N [TILE_WIDTH][TILE_WIDTH]; 
int bx =   blockIdx.x ;   int   by   =   blockIdx.y ; 
int   tx   =   threadIdx.x ;   int   ty   =   threadIdx.y ; 
int Row   = by *   blockDim.y   +   ty; 
int Col   = bx *   blockDim.x   +   tx ; 
float   Pvalue   =   0; 
//   Loop over   the   M and   N tiles required   to   compute   the   P   element 
for   (int   p =   0;   p <   n/TILE_WIDTH;   ++p) { 
//   LOAD:   Collaborative   loading   of   M and   N tiles   into shared   memory 
ds_M [ty][ tx ]   = M[Row*Width   +   p* TILE_WIDTH+tx ]; 
ds_N [ty][ tx ]   = N[(t* TILE_WIDTH+ty )*Width   +   Col]; 
__ syncthreads (); 
//   USE: compute partial - dot - product using current SMEM   tile   values 
for   (int   i =   0; i   <   TILE_WIDTH; ++i) Pvalue   +=   ds_M [ty][i]   *   ds_N [i][ tx ]; 
__ synchthreads (); 
} 
P[Row* Width+Col ] =   Pvalue ; 
}
