MMULT: Handling Matrices of Arbitrary Size 
•   The tiled matrix multiplication kernel we presented so far can handle 
only square matrices whose dimensions (Width) are multiples of the 
tile width (TILE_WIDTH) 
•   However , real applications need to handle arbitrary sized rectangular (but 
still conforming) matrices. 
•   i.e.   such that P=MN where P: j x l, M: j x k, N: k x l 
•   Matrix   sizes may not be evenly divisible by   TILE_WIDTH , in general. 
•   One could pad (add elements to) the rows and columns into multiples of the tile size, 
•   but   this   would   introduce undesirable   space   and data transfer time overhead. 
•   There is a preferable approach we will now discuss.

A “Simple” Solution 
When a thread is to load any input element, test if it is in the valid 2D   data   range 
–   If valid, proceed to load 
–   Else, do not load, just write a 0 in SMEM 
Rationale: a 0 value will ensure that that the multiply - add step does not affect 
the final value of the output element 
–   The condition tested for loading input elements (Load stage) is different from 
the test for calculating output P element (Use stage) 
–   A thread that does not calculate valid P element can still participate in loading 
input tile   elements 
–   LOAD stage: test that input data element is within 2D input matrix data ranges 
–   USE   stage: test that not exceeding inner - product dimension   K 
–   Tests need to account for algorithm phase # and TILE_WIDTH

Handling General Rectangular Matrices 
•   In general, the matrix multiplication is defined in terms of rectangular matrices 
•   A (j x k) M matrix multiplied with a (k x l) N matrix results in a (j x l) P matrix 
•   P = MN 
•   Previously we   considered   square matrix multiplication, a   special   limited   case 
•   The kernel function can be generalized to handle general rectangular 
matrices as follows : 
•   The kernel Width argument is replaced by three   input data   dimensions :   J,   K, L 
•   Where   M : J x K,   N :   K x L,   P : J x L 
•   When   Width is used to refer to the height (#rows) of M or height of P, replace it with   J 
•   When Width is used to refer to the width (#cols) of M or height of N, replace it with   K 
•   K is the “inner product” dimension of the matrix multiplication 
•   When Width is used to refer to the width of N or width of P, replace it with   L

=== p39 ===
Control Divergence 
–   Control divergence occurs when threads in a warp take different 
control flow paths   by making different control decisions 
•   Some take the then - path   and others take the else - path of an if - statement 
•   Some threads take different number of loop iterations than others 
–   The execution of threads taking different paths are serialized in 
current GPUs 
–   The control paths taken by the threads in a warp are traversed one at a time 
until there   are   no more. 
–   During the execution of each path, all threads taking that path will be executed 
in parallel 
–   The number of different paths can   grow for   nested   control flow statements

=== p40 ===
Control Divergence Examples 
–   Divergence can arise when branch or loop condition is a 
function of thread indices 
–   Example kernel statement with divergence: 
–   if ( threadIdx.x   > 10) { } 
–   This creates two different control paths for threads in a block 
–   Decision granularity < warp size 
–   threads 0…9 follow different path than the rest of the threads in the first 
warp 
–   Control flow based on   threadIdx 
–   Example without divergence: 
–   If ( blockIdx.x   > 2) { } 
–   Decision granularity is a multiple of blocks size; 
–   all threads in any given warp follow the same path
