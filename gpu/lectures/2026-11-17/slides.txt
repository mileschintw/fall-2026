The   C onvolutional   L ayer:   General Formulation

A common misconception is “one filter per channel, sum, then K filters”. 
The real structure: K independent filters, each spanning all C channels; 
the channel sum happens inside each filter. 
This is exactly why the GEMM reduction dimension will be C·R·S.

The convolution equation and its three parameters 
Convolution on GPUs: From Direct Kernels to GEMM · Course 1   13 
• X[·] = 0 outside the image: every window that hangs over the border reads zeros for the missing 
taps (this is what pad means in practice) 
• Deep - learning “convolution” is cross - correlation: the filter is not flipped. A flipped - kernel network 
learns flipped weights, so nothing changes algorithmically 
•   stride   —   how many input pixels the window advances per output pixel (stride 2 halves P and Q: 
downsampling   inside the layer) 
•   pad   —   zero rows/columns conceptually added around the image so windows may hang over 
the border; X is read as 0 there (kernels never store the zeros) 
•   dil   (dilation)   —   spacing between the filter taps: tap r lands   dil·r   pixels from the window origin, so 
the receptive field grows to   dil ·(R−1)+1 without new weights 
• Each term of the sum is one multiply - add; the three sums together are the GEMM reduction we 
build in   § 2.3

Receptive field : the set R( p,q ) of input values that contribute to output pixel ( p,q ) for every channel c, 
the R × S window at rows   p·stride−pad+r·dil   and columns   q·stride−pad+s·dil   (the orange square, for all C channels).

2 · Foundations · passes 
fprop ,   dgrad ,   wgrad   —   the three convolution passes of   ML   training 
Convolution on GPUs: From Direct Kernels to GEMM · Course 1   25 
• fprop (forward propagation) computes the layer output Y from the input X and the weights W   —   the only pass 
needed at inference 
• dgrad (data gradient) computes ∂L/∂X from ∂L/∂Y and W: the same weights applied “backwards” (a transposed 
convolution: each output gradient is scattered through the filter to the inputs it came from). It is needed to keep 
back - propagating into earlier layers 
• wgrad (weight gradient) computes ∂L/∂W from X and ∂L/∂Y: for each tap (c,r,s) a correlation of the input with the 
output gradient summed over all images and pixels   —   the learning signal 
• Every pass is a sum of products of the same three tensors with one of them unknown, so every pass is a GEMM 
with the roles of M, N and K_gemm permuted (next slide). Each costs 2 FLOPs per weight per output pixel: training ≈ 
3 ×   the fprop FLOPs   —   the “6·N·D” rule from the earlier lecture, seen per layer

3.6.12 · epilogue fusion 
3.6.12 Epilogue fusion   —   where modern libraries win (bias, activation, residual, 
quantization) 
Convolution on GPUs: From Direct Kernels to GEMM · Course 1   70 
•   After the K loop the output tile is in registers. Anything per - element can be applied 
there for free: + bias, ReLU/GELU/SiLU, + residual input, scale and round to FP 8 /INT 8 
•   Without fusion each of those is a separate memory - bound kernel reading and writing 
the whole activation ( 25.7   MB each way for our   3 × 3   shape) 
•   cuDNN   9   graph API with runtime fusion compiles conv + bias + activation + residual 
into one kernel; CUTLASS's Epilogue Visitor Tree (EVT) composes the same ops as a tree 
of functors over the accumulator fragment 
•   Our kernels have the hook: the epilogue loop in sgemm_tiled / I - series is where a 
fused bias+ReLU would go (one line). Course   3   revisits this for quantized inference 
(FP 8 /INT 4   scales live in the epilogue) 
•   Measure it: time conv alone vs conv+bias+ReLU as three kernels vs one fused   —   the 
fused version is faster by the two extra passes over Y

class Timer { 
float time; 
const uint64_t   gpu ; 
cudaEvent_t   a, b; 
public: 
Timer (uint64_t   gpu =0) :   gpu ( gpu ) { 
cudaSetDevice ( gpu ); 
cudaEventCreate (&a); 
cudaEventCreate (&b); } 
~Timer ( ) { 
cudaSetDevice ( gpu ); 
cudaEventDestroy (a); 
cudaEventDestroy (b); } 
void start ( ) { 
cudaSetDevice ( gpu ); 
cudaEventRecord (a, 0); 
} 
void stop (std::string label) { 
cudaSetDevice ( gpu ); 
cudaEventRecord (b, 0); 
// call   EventSynchronize   prior to   EventElapsedTime 
// to ensure both events have recorded 
cudaEventSynchronize (b); 
cudaEventElapsedTime (&time, a, b); 
std:: cout   << "EVENT TIMING: " << time << 
"   ms   (" << label << ")" << 
std:: endl ; 
} 
};   // end Timer class
