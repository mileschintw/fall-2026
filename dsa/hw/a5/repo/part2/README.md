# Part 2: Mutant hunt (100 points)

You do **not** write a binary search tree in this part. You get one, and its specification, and you
write the tests. We then run your tests against **buggy copies** of the tree, called mutants. Each
mutant has exactly one thing wrong with it. A mutant is **caught** when at least one of your tests
fails, errors or hangs on it. Your grade is how many mutants you catch. Everything for this part is in this
folder, `part2/`.

## AI, and the exams

An AI assistant is allowed here, in `part2/` only. If you point one at your repo, tell it to stay out of
`part1/`. It can help you write a test file that scores well. The midterm and
final are on paper, without AI, and they will ask you to do what this part practices: look at a tree
function, find what is wrong with it, and write the test that would catch it. Use this assignment to make
sure you can do that yourself. A good habit: for every test you keep, be able to say which mistake it
catches and why that mistake is easy to make.

## The specification

The docstrings in `bst_reference.py` and this section are the specification. Every mutant breaks some part
of it.

- **Size.** All five functions must work on any tree built from up to 5,000 values, inserted in any order.
- **Speed.** Each function takes time proportional to the height of the tree, not to the number of values.

## The files

| File | What it is |
| --- | --- |
| `bst_reference.py` | The correct tree: `bst_insert`, `bst_search`, `bst_min`, `bst_max`, `bst_delete`. You do not edit this file. |
| `test_bst.py` | **Your tests go here.** This is the only code file you edit. |
| `AI_NOTE.md` | A short note on how you worked (10 points). |
| `practice_mutants/` | Four buggy copies (`p1.py` to `p4.py`) to practice on. |
| `check_tests.py` | Tells you, on your own computer, what will be checked. |
| `tree_tools.py` | `create_tree_node`, `inorder_values`, `tree_size`, `tree_height`. |

## Run your tests

From the `part2` folder:

```
cd part2
python3 -m unittest test_bst -v      # your tests, on the correct tree
python3 check_tests.py               # everything below, with a summary
python3 check_tests.py mine          # not graded: your tests, on YOUR tree from part1/bst.py
```

The last one is worth running once both parts work. If one of your tests fails on your own Part 1 tree but
passes on the reference, either your tests found a bug in your own code, or they found a difference between the
two parts: Part 1 allows recursion, so your tree may not handle the 5,000-value trees this part requires. Work out
which.

If PyCharm says `ModuleNotFoundError`, right-click the `part2` folder and choose **Mark Directory as > Sources
Root**.

## How you are graded (100 points)

| Part | Points | What counts |
| --- | --- | --- |
| The gate | 15 | Your tests all **pass on the reference**, and at least 8 tests run. A test that fails on the correct tree is a wrong test. |
| Practice mutants | 15 | You catch `p1` (5), `p2` (4), `p3` (3), `p4` (3). Counts only if the gate passes. |
| Hidden mutants | 60 | We run your tests against 21 hidden buggy trees. Counts only if the gate passes. |
| AI note | 10 | `AI_NOTE.md` is filled in. |

GitHub shows the gate, practice and note points (40 of the 75 it shows) when you push. The 60 hidden points
are added by the instructor after the deadline, along with a list of the rules you missed.

The hidden mutants are not all equally easy. Some break something any reasonable test notices; others break
a part of the specification that only a careful reader will test.

## What your tests may and may not do

Test what the functions **do**, not how they are written.

- Allowed imports: `unittest`, `random`, `time`, `copy`, `itertools`, `math`, `string`, `collections`,
  the five functions from `bst_reference`, and the four helpers from `tree_tools`.
- Not allowed: reading files, `inspect`, `os`, `sys`, `import bst_reference`, anything with a double
  underscore such as `__code__`, `eval`/`exec`, and `sleep`. `check_tests.py` tells you the line.
- Tests must be **repeatable**: use `random.Random(seed)`, not an unseeded `random`.
- Keep the whole suite under about 10 seconds on the reference.

## AI note

Fill in `AI_NOTE.md`: which tool, what you asked, what you changed, and one mutant you understand. The note
is graded on being complete and honest, not on whether you used AI. Whoever wrote a test, you are
responsible for knowing which rule it checks.
