From lists to trees
Start by tying off the last three classes in one minute, then ask a question that the rest of the course answers: what if one
node could point to two next nodes?
Last class ended with one idea: an interface can have several implementations, and you choose by which operations
you do most.
The linked list gave us cheap insertion at the front but slow search, O(n), because to find a value you walk the
chain one node at a time.
Today's question is how to do better than walking in a line.
The hook
"If I start with 1,000,000 values and each step lets me throw away half of them, how many steps until one is left?"
The answer is about 20 (220 is 1,048,576).
A line cannot give that, because each step off a linked list only removes one value from the search.
A shape where each step cuts the remaining values in half can.
That shape is a tree
next class we will see exactly how to arrange values so that this works.
Today is about the shape itself and how to walk it.
Trees you already use
Where do we already see trees used?
A folder on your computer: folders hold files and other folders.
A web page: HTML elements hold other elements (the DOM).
A company org chart, a family tree, a tournament bracket.
A Python expression like (8 - 3) * (2 + 4) : Python itself turns it into a tree before running it. We will show that live
at the end of the segment on traversals.

The recursive definition: a binary tree is either empty, or a node with a left tree and a right tree.
"a left tree" can itself be empty, which is how leaves happen.
Everything after this follows from that sentence:
if the tree is defined in terms of smaller trees, then functions on trees can be written in terms of smaller trees too,
with "empty" as the base case.
A linked list is a tree
A linked list is a tree where every node has exactly one child.
That is the degenerate case, and it will matter next class
a lopsided tree can be as bad as a linked list, which is where the worst case of a tree comes from.
Two conventions to say out loud
Books disagree on these and tests pick a side, so tell students to check the question.
We count height in edges, so a single node has height 0 and the empty tree has height −1.
Some books count nodes instead, so the same single node has height 1 and the empty tree has height 0.
The extremes: a perfect binary tree of height h has 2h+1 − 1 nodes (1, 3, 7, 15, ...), so a million values need a height
of at least 19 (220 − 1 = 1,048,575), while a chain of a million nodes has height 999,999.

Where is the tree in memory?
Like the Python list, the tree is a set of objects with references between them, not a block.
Each node is its own dict somewhere in memory, and left and right hold references.
That is the same picture as the linked list from last class, and it carries the same costs: no jumping to an index, and an
object per value (our dict nodes were about 184 bytes per value when we measured the linked stack).
Recursion on trees: size, height, leaves
Because a tree is defined as "empty, or a node with two smaller trees," each function has the same two-case shape:
do something simple for the empty tree
combine the answers from the left and right subtrees for the rest.
Size
What the size of the empty tree is (0)
What is the size of a node is in terms of its two subtrees (1 plus the left size plus the right size)?
def tree_size(node):
if node is None:
return 0
return 1 + tree_size(node['left']) + tree_size(node['right'])

The base case is the one that trips people: with height counted in edges, the empty tree is −1, so that a single node
comes out as 1 + max(−1, −1) = 0.
Other way of thinking about it: number of levels -1.
def tree_height(node):
if node is None:
return -1
return 1 + max(tree_height(node['left']), tree_height(node['right']))
Leaves
This one has a second base case: a node whose children are both None counts as one leaf.
Let students find it, since leaving it out returns 0 for every tree.
def count_leaves(node):
if node is None:
return 0
if node['left'] is None and node['right'] is None:
return 1
return count_leaves(node['left']) + count_leaves(node['right'])
Results on the running example: size 9, height 3, 4 leaves, and on the empty tree, size 0 and height −1.

Depth-first traversals
A traversal visits every node once.
The three depth-first orders use the same recursive skeleton and differ in only one thing: where the line that visits the
node goes, relative to the two recursive calls.

Order The visit line goes... Read as On the running example

def preorder(node, out):

===== p7 =====
 Depth-first goes all the way down one side before coming back.
Breadth-first goes level by level: the root, then its children, then their children.
On the running example it is 8, 3, 10, 1, 6, 14, 4, 7, 13.
Level order with a deque
The idea: keep a list of nodes that are waiting to be visited.
Take the node at the front, visit it, and put its children at the back.
That is a queue, so it uses the collections.deque from last class with popleft :
def level_order(root):
out = []
todo = deque()
if root is not None:
todo.append(root)
while todo:
node = todo.popleft() # queue: oldest first
out.append(node['payload'])
if node['left'] is not None:
todo.append(node['left'])
if node['right'] is not None:
todo.append(node['right'])
return out
The same loop with a stack
Now change two things:
use a plain list
take from the other end with pop() .
Push the right child before the left, so that the left comes off first.
def preorder_with_stack(root):
out = []
todo = []
if root is not None:
todo.append(root)
while todo:
node = todo.pop() # stack: newest first
out.append(node['payload'])
if node['right'] is not None:
todo.append(node['right']) # pushed first, so popped last
if node['left'] is not None:
todo.append(node['left'])
return out
It prints 8 3 1 6 4 7 10 14 13, the same as the recursive preorder.
This is the point:
the two loops are the same loop with the waiting line changed.
a stack goes deep,
a queue goes wide.
the recursive version was already using a stack (the one Python keeps for function calls) which is why the
recursive traversals can be written without one.

Things to note:
First, the height h is the number that matters, and it ranges between about log2 n for a well-packed tree (our 9-node
example has height 3) and n − 1 for a chain.
A million values could mean 19 levels or 999,999, and which one you get depends on the shape, which is the
whole story of next class and the one after.
Second, the width of a perfect tree's bottom level is about half of all the nodes, so level order can need a lot of
memory on a bushy tree, while a depth-first walk only ever holds one path.
The last row, and the hook
Look at the last row:
finding a value in this tree costs O(n), no better than a linked list.
Why do we bother?
"if each step could throw away half."
That needs one more constraint, an ordering rule that tells you which side to look in ==> next class!

The recursion limit:
Python allows 1,000 nested calls by default ( sys.getrecursionlimit() ).
On Python 3.11, tree_height on a chain of 1,000 nodes raises RecursionError , and a chain of 995 still works.
A balanced tree of a million values is only about 20 deep and never comes close, but a lopsided tree can hit this, which
is one more reason shape matters.
Do not just raise the limit; use the stack-and-loop (iterative) version, which is limited by memory instead.
ast . The module ast exposes Python's own syntax trees. ast.walk is a few lines with a deque and popleft in the
CPython 3.11 source, so in practice breadth-first, although its docstring says "in no specified order".
ast.NodeVisitor walks depth-first.
Folders. os.walk is a tree walk over the file system, and it yields each directory before the ones inside it by default.
Other languages. The same structure shows up everywhere. In Java, TreeMap is built on a tree, and in C++,
std::map is usually one as well, which we will come back to when we cover balancing.
Wrap-up
A tree is a node with smaller trees hanging off it, so recursion is the natural tool
A stack gives depth-first order and a queue gives breadth-first order
Every cost we care about depends on the height.
You need Reach for Cost to remember
Size, height, or leaves of a tree recursion with the empty tree as the base case O(n) time, O(h) space
Visit every node, parent first preorder O(n)
Visit every node, children first postorder O(n)
Visit level by level a deque with popleft O(n) time, O(w) space
Depth-first without recursion a list used as a stack O(n) time
The height of a tree with n nodes depends on the shape between about log2 n and n − 1
A million values in a perfect tree height 19 against a chain at 999,999
